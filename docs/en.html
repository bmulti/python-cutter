About this application (16 languages)

[intro] Python Cutter — what this application does Python Cutter examines Python source files and catalogues the functions, asynchronous functions, classes and class members they contain. It uses Python's abstract syntax tree (AST) to identify definitions without running the source. The application metadata is Python Cutter, version 44, project Python. The standalone window also uses the internal display version 4.5.0. Choose a source folder on Files, decide whether to scan subfolders with Recursive, then select a file. Definitions shows the parsed definitions, Source / Definition shows complete source or the selected definition, and Class Members lists methods and class-level assignments. Mongo Records can store the extracted definitions in MongoDB. HTML Publish exports the currently displayed Treeview into HTML reports. Log records scans, warnings and actions. Python Cutter supports standalone operation, an optional file or directory argument, and attachment to another Tkinter application using attach(parent, context=None). Its principal interface tabs are Notes, Files, Definitions, Source / Definition, Class Members, Mongo Records, HTML Publish, Config, UI Choices when enabled, and Log. The Treeviews use shared definitions and support heading sorting and HTML, CSV and JSON export controls. A directory scan looks for .py files. It reads each file using UTF-8 with replacement for undecodable characters, then attempts an AST parse. An invalid Python file can still appear in the Files listing with zero definition counts; the parse problem is written to Log. A selected file is parsed in a worker thread to keep the interface responsive. No code from the scanned file is executed merely by scanning, selecting or previewing it. IMPORTANT: Run File DOES execute the selected Python program in a separate process using the configured Python executable. Only run trusted source. Opening an ordinary Python file also automatically queues its extracted records for MongoDB when the database connection is active; the Save Current Definitions button is not the only database write operation. A definition checksum uses MD5 of the definition name and extracted source text rather than its filename, so identical definitions in different files can share a MongoDB key and overwrite the same catalogue record. Back up the MongoDB collection if these records are important. Application settings are saved to cc_python_cutter.json in a writable per-user configuration directory. On Windows this is under APPDATA/CC Python Cutter; on macOS it is under Library/Application Support/CC Python Cutter; on Linux it is under XDG_CONFIG_HOME or ~/.config/CC Python Cutter. If the per-user file does not yet exist, an older cc_python_cutter.json beside the program can be read as the initial configuration. The program remembers up to 15 recent source folders, the scan mode, appearance and last tab. This is the external help file cpc_python_cutter.en.txt. Python Cutter reads it from beside the application, or falls back to python_cutter.en.txt. Its own Notes display generates the tab headings and clickable links from the section identifiers, so the headings are not repeated as Markdown # lines here. [tab:notes] The Notes tab opens this external English help file in a read-only text view. The section markers in square brackets are used to build clickable links to the application's corresponding tabs. Clicking a tab section heading switches to that tab when it exists. The application does not read this file as program code, and editing the help file does not change Python Cutter's source analysis behaviour. The Notes loader checks cpc_python_cutter.en.txt first and python_cutter.en.txt second. If neither file exists beside the application, an explanatory missing help message is shown. If a file is found but cannot be read, its error is displayed in the Notes area. The source uses a custom Notes text widget rather than automatically attaching the shared cpc_notes interface. [tab:files] Files lists .py files found in the chosen source directory. The controls are Source directory, its recent-folder drop-down, Browse, Scan, Open File and Recursive. Browse selects a folder and immediately starts a scan. Scan rereads the current folder. Open File selects a single Python source file to inspect. The Recursive checkbox determines whether subdirectories are included. The table displays full path, filename, last modification time, size, line count, definition count and class count. Definition count includes all AST FunctionDef and AsyncFunctionDef nodes, including methods and nested functions; class count includes AST ClassDef nodes. Click a column heading to sort using the shared Treeview controls. Export buttons create HTML, CSV or JSON from the visible table. Selecting a file loads and parses it and refreshes the other inspection tabs. Double-clicking opens the Definitions tab for that file. The selection is stored as the current file for source viewing, optional database persistence and Run File. Parsing occurs in the background; large directories can take longer while rows are added in batches. An invalid file is logged rather than silently omitted from the directory table. The folder history contains at most 15 unique absolute paths, with the most recent first. The last directory and the Recursive setting are saved between runs. The program does not rename, edit or delete the source files during normal scans. [tab:definitions] Definitions shows the extracted AST definitions and classes for the selected Python file. Each entry displays Type, Title, Arguments, Origin, Lines, Created, Checksum and Keys. Type distinguishes def, async def and class. Arguments are reconstructed from parameter names and include variable positional and keyword parameter markers when present. Class entries show the __init__ signature when it exists. The Lines field is the definition's span in the source. Created is derived from the source file's modification timestamp, not a separate historical creation time for the definition. Keys are AST names encountered within the definition; they are not a comprehensive dependency or type analysis. Checksum is an MD5 digest of the definition name and extracted source. Selecting a row shows that definition's extracted source in Source / Definition. Double-clicking a function opens Source / Definition. Double-clicking a class opens Class Members filtered to that class. Holding the Alt modifier while double-clicking opens the complete file source instead. Open Full Source displays the entire selected file, Run File starts the selected Python source, and Depth Lifter attempts to open the separate Depth Lifter application for deeper inspection. The Definitions Treeview also supports shared HTML, CSV and JSON export buttons. The source is not changed by these inspection actions. [tab:source-definition] Source / Definition is a read-only source inspector with vertical and horizontal scrollbars. The title at the top identifies the current file or selected definition. Selecting a definition replaces the displayed text with its original extracted source, including the relevant body lines. Full Source restores the whole file in the view. The text widget is disabled after loading, so this tab is not a source code editor. Run File launches the current Python file with subprocess.Popen using the Python executable specified in Config, with the file's folder as the working directory. This action can produce any effects of the selected Python program. It does not provide a sandbox or safety inspection. The program reports a launch attempt in Log, but execution of the external process is not the same as confirming its completion. Depth Lifter dynamically imports cc_depth_lifter and attempts to create a new top-level Depth Lifter window for the current file. If that module or its expected DepthLifterApp interface is unavailable, an error is displayed and logged. Opening that separate tool does not rewrite the selected source inside Python Cutter. [tab:class-members] Class Members lists entries extracted from classes in the current file. Columns include Class, Member Type, Member, Arguments, Line and Origin. Member types are regular method, asynchronous method and attribute. The attributes are assignments or annotated assignments directly in the class body. Methods are identified directly inside a class AST body; this is not a dynamic inspection of inherited attributes at runtime. When a new file is loaded, the tab shows members from that file. Double-click a class in Definitions to narrow the member list to just that class. The Line column reports where each member begins in the source, allowing quick reference back to the original definition. Shared controls export the currently displayed table to HTML, CSV or JSON. [tab:mongo-records] Mongo Records displays definitions stored in the configured MongoDB database. The default connection is mongodb://localhost:27017/, database bmulti, collection PYTHON_CODE. The Config tab can enable or disable persistence and change the URI, database and collection. MongoDB access requires pymongo and a reachable MongoDB server; local AST inspection does not depend on a working database connection. Refresh retrieves records and lists Type, Title, Arguments, Origin, Lines, Created and Checksum. Save Current Definitions explicitly writes the current file's parsed definitions, using a MongoDB update with upsert for each checksum. When a file is loaded and MongoDB is already connected, the same kind of save is also queued automatically. MongoDB reads and writes use background threads to avoid blocking the Tk interface. IMPORTANT: The document _id is the MD5 checksum of the definition name plus its source text. Consequently, two different paths with identical named definitions may share one stored document. Reading the catalogue and saving to it do not modify the original .py files, but upsert may replace the stored metadata for a matching checksum. A database failure is reported through status and Log rather than preventing local source inspection. [tab:html-publish] HTML Publish exports one selected live Treeview: Files, Definitions, Class Members or Mongo Records. Choose the Treeview, Publish directory, Title and Document description. Selected rows only limits the result to selected rows; leave it unchecked to publish the view's available rows. The source passes the current Treeview directly to the shared HtmlTree publishing function rather than generating a complete source-code website. Publish Page generates the selected table's HTML output. Publish + Update Index also asks the shared publisher to rebuild the index for the output folder. Open Publish Folder opens that directory using the operating system's file manager. The default folder is python_cutter_reports beside the application, but a different directory may be selected and saved. The Treeview export buttons on Files, Definitions, Class Members and Mongo Records provide additional HTML, CSV and JSON outputs. HtmlTree publishing may write additional supporting data files according to the shared cpc_treeviews implementation. Existing generated output filenames may be replaced; keep an independent copy of valuable reports before republishing. No FTP deployment, GitHub upload or remote publishing is performed here. [tab:config] Config controls the Mongo persistence checkbox, Mongo URI, Mongo database, Mongo collection and Python executable. Save Config writes the settings to the per-user cc_python_cutter.json and normally reconnects the MongoDB client. Reconnect Mongo saves the current UI values and starts a new connection attempt. The Mongo Records tab reports connection status. Source directory and Recursive are set on Files, while HTML publishing folder is set on HTML Publish; these settings are included in the saved configuration. The directory history and last used directory are also remembered automatically. The current window dimensions and last tab are saved on normal shutdown, along with theme and density settings. Changing Python executable affects only later Run File actions. It does not change the interpreter that is already running Python Cutter or the parser used by its built-in AST analysis. MongoDB persistence is optional, but turning it on permits background database writes when files are loaded. [tab:ui-choices] UI Choices uses the shared cpc_ui_choices component when available and the tab is enabled. It manages theme, density and window preferences through the common interface. In attached mode the host application's appearance takes priority. If the shared component is unavailable, the tab explains that it could not attach; the rest of the source-inspection controls remain available. Theme and density choices are stored in the per-user configuration. The standalone window normally starts at 1380 × 860 pixels, with a minimum size of 900 × 620 pixels. The saved geometry is used on later launches. This appearance control does not alter any Python source being inspected. [tab:log] Log displays timestamped information about scans, loaded files, database connection and save attempts, launching Python files, opening Depth Lifter, and HTML publication. It also reports parse warnings for files that cannot be analysed with AST and shows errors from background work. This is useful when a directory contains invalid or incomplete Python files. The Log is a read-only application view, not an editor and not a persistent per-operation log file created beside each source file. The supplied code appends messages to the current Log widget; entries are not automatically saved as a separate durable report. Export the relevant information using another method if a permanent audit record is required.
